配置备份 / 恢复

导出的是一个包含令牌、设置与全部备注的 JSON，换设备时导入即可。 备注已经会自动同步到仓库（见上一张卡片），所以这个导出主要是用来备份令牌与兜底。

它是怎么工作的

  1. 评论者在 Twikoo 里留下邮箱，Twikoo 对邮箱做 trim().toLowerCase() 后计算 SHA-256，得到 64 位十六进制串。
  2. Twikoo 拼出头像地址：https://<你填的 CDN 基址>/avatar/<sha256>?d=mp。
  3. 这个地址被解析到你的 GitHub 仓库里的 avatar/<sha256> 文件——也就是你在本工具上传的那张图。

所以：图片必须放在仓库的 avatar/ 目录下且不带扩展名，CDN 基址里则不能带 /avatar。

四步跑起来

  1. 建图床仓库：GitHub 上新建一个 Public 仓库（jsDelivr 无法读取私有仓库），勾选 Add a README 以便有初始提交。
  2. 建令牌：Settings → Developer settings → Personal access tokens → Fine-grained tokens，只授权这一个仓库，权限选 Contents: Read and write。
  3. 填设置页：粘贴令牌、填 owner / 仓库名 / 分支，点「测试连接」。
  4. 上传头像：在上传页填邮箱 + 拖入图片，上传成功后到「CDN 与 Twikoo」页复制 GRAVATAR_CDN，填进 Twikoo 后台的「头像 CDN」。

必须知道的几个坑

  • QQ 邮箱不走这里。Twikoo 对 12345@qq.com 或纯数字 QQ 号会直接调用 QQ 头像接口，连自定义 CDN 都不用。
  • 仓库必须公开。jsDelivr 只能读取公开仓库；私有仓库需要自带令牌的反代，本工具不支持。
  • 无扩展名与 Content-Type。jsDelivr 不嗅探内容、只按文件名判定 MIME，所以哈希命名的文件会返回 application/octet-stream（带 nosniff）。这个组合在 Chromium/Edge 上实测能正常显示——浏览器在 <img> 场景仍会解码图片；真正会被拦的是 text/plain + nosniff，而本方案不会落到那一组合。Firefox / Safari 未实测。严格校验 MIME 的场景（CSS 背景图、图片代理、社交平台抓头像）建议用下一条的加固方案。
  • 加固方案。仓库里附带了 extras/cloudflare-worker.js，用一个免费 Cloudflare Worker 反代 jsDelivr 并按文件魔数强制返回 Content-Type: image/*，然后把 CDN 基址换成自己的 Worker 域名即可。上线前也可以先确证自己仓库的真实响应头：curl -sI "https://cdn.jsdmirror.com/gh/你/仓库@main/avatar/某个sha256"。
  • 换了头像评论里还是旧的？分两种情况：cdn.jsdelivr.net / gcore.jsdelivr.net 是 jsDelivr 自家的节点，本工具会在覆盖/删除后自动调用它的 purge 接口立即刷新（也可以在「图库管理」里选中图片手动点「刷新 CDN 缓存」）。而 cdn.jsdmirror.com 是第三方镜像（腾讯 EdgeOne），有自己的多级缓存，purge 对它无效——实测它没有公开的刷新接口，缓存最长约 24 小时（浏览器侧 5 分钟）。想让它立刻生效：在 Twikoo 里把 DEFAULT_GRAVATAR 从 mp 改成别的值即可让所有头像 URL 变化、绕过旧缓存，或者换用能 purge 的线路。
  • Token 安全。令牌存在浏览器里，请使用最小权限的细粒度令牌，并避免在公共电脑上勾选「保存在浏览器」。

关于邮箱备注

SHA-256 不可逆，仅凭文件名无法知道是谁的头像。本工具会在你上传时把「邮箱 ↔ 哈希」记录下来，于是图库里能直接显示邮箱、能按邮箱搜索。

这份备注会自动同步到 GitHub 仓库里的一个文件（默认 .youtiao/notes.json），所以换设备、清浏览器缓存都不会丢。本地也留一份缓存，离线照样能显示。

要注意：图床仓库必须是公开的，所以备注写进同一个仓库 = 所有评论者的邮箱公开可读。因此第一次写入前会让你选一次，也可以把备注放进一个独立的私有仓库（设置页有「创建私有备注仓库」按钮）。
